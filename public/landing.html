Core Architecture

Three Pillars of Ecosystem Security

Deterministic pre-signing security across the Base blockchain. In-memory inspection with zero private key custody.

PILLAR // 01

Website & Domain Security

Deterministic URL verification that checks inbound links against the authoritative Base Official Domain Registry before an attacker can mislead a user or autonomous AI agent.

  • 17 Verified Official Domains: Registry verification for base.org, basescan.org, aerodrome.finance, and core ecosystem services.
  • Cyrillic & Homoglyph Lexer: Punycode deobfuscation catches lookalike character spoofs invisible to human eyes and multimodal LLMs.
  • 100% In-Memory SSRF Airgap: Zero outbound network fetching. Attackers cannot probe internal subnets or fingerprint agent IPs.
  • Privacy-Preserving Redaction: High-entropy reset tokens, bearer credentials, and query secrets sanitized automatically.
PILLAR // 02

Token & Smart Contract Security

Real-time screening of smart contracts and ERC-20 assets on Base Mainnet (8453) powered by GoPlus intelligence and automated EVM bytecode analysis.

  • Honeypot Contract Detection: Exposes hidden transfer restrictions, transfer blacklists, and anti-sell backdoors before swapping.
  • Predatory Tax Screening: Detects 99% sell tax siphon traps, hidden owner privileges, and proxy implementation risks.
  • Calldata Function Decoder: Inspects EVM 4-byte selectors, decoding unverified spender approvals and signature permits.
  • Sanctions & Drainer Screening: Cross-checks counterparty addresses against phishing lists, theft wallets, and OFAC sanctions.
PILLAR // 03

Base Wallet Security

Automatic, read-only token discovery and portfolio threat screening for any public Base wallet address without requiring signature permissions or private keys.

  • Automatic Token Discovery: Read-only retrieval of ERC-20 token holdings via Blockscout Base v2 API and canonical registries.
  • Token Impersonation Sentinel: Detects fraudulent tokens mimicking official Base assets (e.g., fake USDC, spoofed WETH).
  • Zero-Custody Boundary: PayGuard never requests seed phrases, private keys, or transaction signing permissions.
  • Portfolio Risk Breakdown: Highlights unsolicited scam airdrops and high-risk contracts held in wallet.

Critical Realities of Web3

Why Traditional Security Assumptions Fail

Phishers and scam token deployers exploit false senses of security. PayGuard is engineered around three non-negotiable realities:

HTTPS ≠ Legitimate Website

A valid SSL padlock certificate proves only that the connection is encrypted — not that the entity on the other end is genuine. Phishing sites obtain automated SSL certificates in under two minutes.

PAYGUARD DEFENSE: Evaluates domain identity against authoritative Base ecosystem registries and flags typosquats (e.g. bases.org vs base.org).

Verified Source ≠ Safe Contract

Verified Solidity source code on block explorers simply means the code matches bytecode — not that it is safe. Malicious contracts regularly feature verified code hiding 99% sell taxes and transfer locks.

PAYGUARD DEFENSE: Inspects contract bytecode logic, dynamic transfer restrictions, and GoPlus honeypot telemetry on Base Mainnet.

Token Symbol ≠ Authenticity

ERC-20 token names and ticker symbols are completely unreserved in EVM architecture. Anyone can deploy a token named "USDC" or "cbBTC" to deceive traders and automated trading agents.

PAYGUARD DEFENSE: Compares contract addresses against the canonical Base token registry to identify impersonator tokens in wallets.
