Core Architecture

What PayGuard checks

Three checks cover the main risks before a Web3 interaction.

PILLAR // 01

Website & Domain Security

Checks Base-related domains for lookalikes, Unicode tricks and suspicious URL patterns. The supplied page is not opened.

  • Domain registry: Compares hostnames with 17 curated Base ecosystem domains.
  • Lookalike detection: Checks Unicode and Punycode hostnames.
  • No page fetch: URL analysis does not open the supplied website.
  • URL redaction: Removes sensitive URL values from displayed reports.
PILLAR // 02

Token & Smart Contract Security

Screens Base token contracts with GoPlus security data.

  • Honeypot signals: Shows provider-reported sell and transfer risks.
  • Tax and controls: Reviews reported tax levels and privileged controls.
  • Calldata inspection: Decodes common ERC-20 transfer and approval calls.
  • Address screening: Checks available phishing, theft and sanctions indicators.
PILLAR // 03

Base Wallet Security

Scans supported Base wallet token holdings using public data. Discovery coverage depends on the available indexer and RPC services.

  • Token discovery: Uses Blockscout when available, with a curated-token fallback.
  • Impersonation checks: Compares asset addresses with supported canonical tokens.
  • Read-only: No seed phrase, private key or signing permission is requested.
  • Findings: Groups provider flags and unverified assets.

Critical Realities of Web3

What to check before you trust

Three things to check before trusting a Web3 interaction.

HTTPS ≠ Legitimate Website

HTTPS encrypts a connection. It does not prove that a website is the official one.

PayGuard check: Evaluates domain identity against authoritative Base ecosystem registries and flags typosquats (e.g. bases.invalid vs base.org).

Verified Source ≠ Safe Contract

Verified source code does not prove that a contract is safe to use.

PayGuard check: Uses GoPlus token-security data to report known honeypot, tax and transfer-risk indicators.

Token Symbol ≠ Authenticity

Token names and symbols can be copied. Check the contract address, not just the ticker.

PayGuard check: Compares contract addresses against the canonical Base token registry to identify impersonator tokens in wallets.
FAQ

Frequently Asked Questions

Simple answers about PayGuard’s checks and limits.

Never. PayGuard is strictly read-only and non-custodial. It never asks for, stores, or handles private keys, seed phrases, or wallet signature permissions. URL checks parse the supplied target without opening the page. Token and wallet checks may query security providers such as GoPlus or Blockscout. Calldata decoding is read-only. PayGuard does not request a seed phrase, private key or transaction signature.
PayGuard maintains an authoritative registry of 17 verified official Base ecosystem domains (including base.org, basescan.org, aerodrome.finance, and coinbase.com). When an incoming URL is inspected, PayGuard uses Unicode Punycode lexing to catch lookalike homoglyphs (such as Cyrillic 'а') and detects typosquats like bases.invalid.
Server-Side Request Forgery (SSRF) occurs when a security scanner blindly fetches an attacker's link. Attackers exploit this to port-scan local services or deanonymize the agent's IP address. PayGuard parses URLs purely in-memory using static lexical analysis — zero outbound TCP or HTTP connections are made to the target host.
PayGuard uses Blockscout Base data when available and checks supported token contracts with GoPlus. Discovery can be partial when the indexer is unavailable; the result shows that limitation.
No. PayGuard provides advisory pre-signing intelligence. It does not control user wallets and cannot unilaterally intercept or block transactions on-chain. For AI agents, PayGuard provides policy hooks that enforce agent-side pre-execution rules.
